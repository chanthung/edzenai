
Goal: fix the parent links generated by the Students page so manual links work the same way as the WhatsApp-delivered links.

What I found
- The parent portal itself is not the core problem: the same `access_token` works when the link is sent through WhatsApp.
- `ParentView` only uses the `token`, so the name slug is cosmetic and not causing the failure.
- The inconsistency is in link generation:
  - `src/pages/admin/Students.tsx` builds Copy/Open links from `window.location.origin`
  - `supabase/functions/send-parent-link/index.ts` builds WhatsApp links with `https://www.edzenai.com/...`
- Because those flows use different hosts, Copy/Open can point to a non-canonical domain while WhatsApp points to the working public domain. That explains why the page shell loads but then shows “Link Not Found”.

Implementation plan
1. Standardize parent link generation
- Create one small frontend helper to:
  - slugify the student name
  - build `/view/:name/:token`
  - build the full public parent URL using the working live domain
- Replace the current `window.location.origin` usage in `src/pages/admin/Students.tsx`.

2. Fix all manual parent-link actions in Students
- Update:
  - Copy button
  - External/open-link button
- Make both use the same canonical public URL as WhatsApp, so all parent links are identical regardless of how they are opened or shared.

3. Align backend-generated links too
- Keep `send-parent-link` on the same canonical URL.
- Also update other messaging functions that generate parent links so they cannot drift again:
  - `supabase/functions/send-fee-reminders/index.ts`
  - `supabase/functions/send-payment-confirmation/index.ts`

4. Add a small safety cleanup
- Use one shared slug-building pattern everywhere.
- Optionally improve button wording/tooltips so it’s clearer that:
  - “Share” sends via WhatsApp
  - the external icon opens the parent portal directly

5. Verification
- Test one student from `/admin/students` using:
  - Copy
  - External/open icon
  - WhatsApp send
- Confirm all 3 open the exact same parent portal on the same domain and no longer show “Link Not Found”.
- Check the flow on mobile as well, since parents will commonly open these links there.

Files likely to change
- `src/pages/admin/Students.tsx`
- `src/lib/...` (new helper for parent link building)
- `supabase/functions/send-parent-link/index.ts`
- `supabase/functions/send-fee-reminders/index.ts`
- `supabase/functions/send-payment-confirmation/index.ts`

Technical note
- No database migration is needed.
- No change is needed to the parent-token RPC itself unless testing shows a second issue after URL standardization.
- I will use the same currently working public domain used by WhatsApp for all parent links so the behavior becomes consistent.
