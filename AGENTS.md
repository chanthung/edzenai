# Project rules

- Teacher downloads use a blank, styled workbook asset compatible with the shared import parser and an allowlisted client-side export of the RLS-scoped saved teacher query; reject mixed-school results and omit account identifiers/secrets to avoid leaking tenant data.

- Teacher Employee IDs are generated by a database trigger (school-scoped EMP-NNNN, advisory-locked) and locked once set; the UI never edits them — keeps IDs stable and collision-free.
- Teacher HR employment_status is separate from is_active (login access) — changing HR status must never block sign-in.
- Teacher HR import uses shared pure validation/outcome helpers and a user-JWT Edge Function verifying exact school_admins membership; writes only allowlisted HR fields and returns per-row outcomes, preserving names, account links, IDs and assignments. Email is optional: blank-email rows create HR-only records (user_id/email NULL = "Not invited", no login access), Employee ID matches existing records, and unmatched valid emails may be saved on unlinked HR-only records — the import never creates auth accounts. Optional invalid fields are omitted, safety failures skip only their row, and header mapping shares the same parser.
- Invite acceptance links a matching HR-only teacher record (by Employee ID, else exact unique name) instead of inserting a duplicate; it only attaches user_id/email/role and preserves the Employee ID and HR details.
- Add User permits an email already stored on exactly one unlinked HR record only when name and supported role agree; linked or ambiguous matches remain blocked to preserve existing invitation behavior safely.
- Global Admin access badges use the authoritative effective-state RPC; explicit paid renewals align lifecycle anchors and clear termination, while invoice-only edits never alter access expiry.
- Context-sensitive help uses the shared `src/components/ui/field-help.tsx` patterns (FieldHelp popover, FieldHint, SystemGenerated) — never per-screen tooltip logic; popovers are portal-based so they are not clipped by scrollable dialogs.
- Teacher account-linking status is derived only from persisted state via `src/lib/teacher-account-status.ts` (user_id → linked; else exact normalized-email match against unaccepted user_invites → pending/expired; else not_invited) — never infer invitation status from email presence alone.
- Existing-teacher invitations store `user_invites.target_teacher_id`; issue/resend/complete run only through service-role database functions that lock and revalidate the exact record, and acceptance never falls back to inserting a teacher — prevents duplicates and cross-school linking.
